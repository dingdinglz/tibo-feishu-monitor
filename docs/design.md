# 设计与运行语义

本文件记录采集、去重、发送与故障恢复的约定，便于维护时检查行为是否发生变化。

## 分工

```text
Go 主进程
 ├─ 单实例文件锁
 ├─ 顺序采集循环 → source:x → Python 子进程 → twscrape → X
 │                 stdout: 单个 JSON，stderr 不转存
 │              → source:codex-resets → 公共 HTTPS API
 ├─ 可选独立每日调度 → API 状态 + 完整历史 → 每日卡片队列
 ├─ SQLite：帖子、上下文缓存、采集进度、每帖子/目标卡片队列、重置概率、故障状态
 └─ 每个启用目标独立 worker → TypeSafe 判断/成功缓存 → 飞书 Webhook
```

Python 不是常驻 HTTP 服务；每次采集都是有超时上限的子进程。Python 不拥有业务去重状态；Go 在一次数据库事务中保存帖子、发送任务和分页进度，避免“抓到但没有入队”后丢失。

## 采集状态

- `baseline`：首次有效采集的开始时刻，此前发布的历史帖子不推送。请求失败不初始化。
- `last_request_success`：最近一次成功取得有效头页的开始时刻。
- `last_complete`：最近一次从头扫描确认达到目标窗口边界的开始时刻；不因部分分页而更新。
- `cursor / scan_since / scan_started`：未完成扫描的续页和固定窗口。续页跨轮保持窗口不动，防止每次推进时间边界而丢弃中间数据。

没有新帖子与没有取到有效数据是两回事。超时或部分抓取的有效内容可以先持久化，但完整进度保持原值。长时间停机或过期续页超过自动补抓窗口，会明确通知未覆盖区间的风险；窗口外尚未抓到的内容不自动刷群。

只刷新一个最新头页并接续旧游标，不能证明这期间新增的多页内容已经全部覆盖。因此续页到达边界后会安排从头复核，不能直接将整个窗口标成完整。X 返回内容本身仍可能受可见性、删除、排序或接口限制影响。

## 发送状态

- 帖子 ID 与发送任务去重键分离。任务键包含帖子 ID、目标稳定 ID；旧分片序号字段保留兼容性，新帖子只创建序号 0 的一张卡片。
- 每条帖子/回复独立一张 Card 2.0，不合并多条新增，也不将长帖拆成多张卡。队列保存结构化原文；发送时生成卡片并按最终 JSON 字节预算截断预览，保留明确提示和原帖链接。
- 每个目标独立排队；单个目标按已知发布时间从旧到新处理，告警优先，调试卡片最低优先级。
- 启动时将旧普通帖子仍未完成的分片合并为一张卡片，保留第一条未完成任务的 ID、重试时间和尝试次数，其余未完成分片标记为 superseded；已成功记录不变。
- 发送前持久记录尝试次数、限速时间；只有 HTTP 与业务响应都确认成功后才标为已发送。
- 不设置易丢失的纯内存“已发送”状态，也不把超时当成成功。
- 未确认发送在进程崩溃后仍为待发送，可能重复，但不静默丢弃。
- 永久配置错误暂停该目标，重启解除暂停；临时错误保留任务并退避。
- 服务端较长的冷却时间适用于整个目标，告警也不能绕过它。

新增目标不补旧帖子；禁用目标不创建新任务；重新启用继续原有积压。前缀和签名在每次尝试时应用，URL/密钥变更不改变任务身份。

## Codex Resets 来源与每日状态

- `source` 默认 `x`，接受 `codex-resets` 和官方文档 URL。API 模式跳过 X 路径/凭据与 TypeSafe 配置，不额外启动 Python。
- `codex_scan` 与 X 的 `scan` 独立，首次成功静默建立基线；`codex_resets` 表与 `posts` 独立去重。切换来源不删除另一来源的进度和待发任务，不会复用不兼容的分页游标。事件任务键为 `reset:<API ID>:<destination>`。
- API 客户端只读，检查响应结构、字段及完整分页，限制响应大小、页数和总超时；分页失败不提交扫描进度，也不拿部分历史冒充完整统计。HTTP 限流通过 Retry-After 反馈给采集/日报调度的退避逻辑；两者共用客户端冷却期限，避免日报绕过采集限流，但正常请求不串行阻塞。
- 普通 API 轮询同时读取 `/status`，不依赖日报/debug 开关。有效 `active_watch` 单独生成“可能重置 / AI 预测”卡片，首次发现即通知，不受已执行重置的静默基线/补抓窗口限制；历史和状态读取失败独立处理，不丢弃另一方已取得的事件。
- watch 没有 API ID，使用来源及 UTC 观测时间的哈希在 `codex_watches` 表去重，与 `watch:<哈希>:<destination>` 任务原子保存。同源同次观测的概率/正文/有效期修订不重发；重启、预测消失后再出现不重复，新目标不补旧预测。`null` 和发现时已过期的预测不入队；已入队预测沿用发送重试并保留原有效期，始终标明是预测快照。它不进入重置次数统计，也不进入 TypeSafe。
- 每日调度是独立 worker，每 30 秒按配置时区检查 HH:MM，按本地日期去重。夏令时重复时段不重复入队，跳过的时刻在下一个有效时刻补发。重启只追补今天；API 错误不消耗名额。
- 日报通过 `daily:<本地日期>:<destination>` 在 SQLite 中原子入队；不依赖内存中的 last-sent。当天已有任务（包括成功、待重试）不重新请求 API；新启用目标除外。次日入队同时将旧的待发日报标为 superseded，其他消息不变。
- 日报保存有时间标记的完整快照，使用既有多目标限速、签名、字节预算和发送重试；没有针对日报的临时直发通道。关闭调度只阻止新任务，已入队任务保留。
- API 重置/预测/日报记录不是 `model.Post`，不进入 TypeSafe。`regular`、`banked`、网站观测、待执行预告、AI watch 保持各自语义；过计划时间不自动认定执行，过期 watch 不显示。
- 最长间隔仅从完整且与 status 数量/最新 ID 及时间匹配的历史计算，其他统计取 status；不模拟 API 未提供的挑战进度。展示始终包含 Codex Resets 来源链接。

## 重置概率

- 统一在发送 worker 中调用 TypeSafe Noul，普通帖、回复、引用、旧积压和 debug 帖子走同一条路径；不在 `ApplyScan`/`QueueDebug` 的数据库事务里访问外部 API。
- `state` 包含当前帖子、可见父帖/引用和同作者此前有限条动态。历史以当前帖子时间为上限，同秒用十进制字符串 ID 比较，排除当前帖、未来帖和过期历史。正文预算独立于卡片截断预算。
- 成功判断持久化到 `reset_assessments`，缓存键含问题版本、模型配置、历史配置及批次。普通帖子多目标/重试共享成功判断；debug 的纳秒批次键隔离每次测试，下一轮真实重新请求。推理串行合并，避免同一帖子多目标同时重复调用；飞书发送和采集仍独立。
- 未配置 Key 或服务失败不阻止原帖推送：概率区显示“暂不可用”，既不伪造概率，也不缓存失败为成功。下一次尝试或新的 debug 批次可重新判断。
- 百分比来自经验证的 `[0,1]` Noul 值（不是 Score/confidence）；原始 0 是合法值，与缺失区别显示。进度条仅是概率可视化，不代表额度剩余或重置完成程度。

## 告警与凭据

采集失败、覆盖不完整和发送失败分别记录故障状态；达到阈值并经过冷却后才创建告警任务，恢复后只创建一次恢复通知。永久发送配置错误立即提醒其他可用目标；失败的告警不递归生成告警。

业务库不保存 Webhook、签名密钥、TypeSafe API Key 或账号 Cookie。凭据只在配置与进程环境中出现，HTTP 错误不包含原始 URL/响应文本。Python 错误只跨进程传递固定类别，防止上游异常带出账号或代理密码。

## 不在初版范围

- 图片上传、翻译、摘要、对已实际发生的额度重置做权威核验。卡片仅做展示和打开原帖，不实现交互回调。
- Web UI、Docker、群内命令、飞书应用机器人。
- 自动登录、验证码处理、通过重置锁或切换账号绕过限流。
- 自动修改已有账号库权限、启动自动测试推送、自动安装或启动系统服务。
- 热加载、多实例高可用、严格跨网络恰好一次。
