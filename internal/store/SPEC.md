# 持久状态与事务队列

## 职责

拥有业务 SQLite 的建库/迁移、来源状态、发现记录、发送队列、故障状态和成功推理缓存。发现记录与目标任务在同一事务提交；具体去重键、目标启停、来源隔离、日报替换和旧分片升级契约见 `tibo-architecture`。

运行期发送策略由编排层在 worker 启动前设置，运行中不修改；低层存储的零策略保留无限制语义。入队检查事件资格，`Claim` 对所有任务类型执行时间边界过滤；历史保留与显式重放语义见 `tibo-architecture`。

写连接使用单连接、WAL、FULL 同步和外键约束。格式化由调用方传入函数，格式失败回滚同一事务；本包不导入飞书实现。

## 所有权与持久性边界

`Claim` 不是租约：它记录尝试次数及目标节流时间，任务仍为 pending，直到显式确认发送。正确性依赖外层进程锁和每目标单 worker，不能仅因 SQLite 支持并发就增加多个消费者。

业务库绑定目标用户；只保存目标身份和运行状态，不保存 Webhook、签名密钥、Cookie 或推理密钥。记录不自动清理，删除去重状态会改变重启行为，磁盘容量与备份由运维负责。

**未确认的长期约束（由现有导入关系推断）：**持久层仅依赖配置类型与领域类型，不调用网络、子进程或编排器。
