# 通知记录、卡片与 Webhook 传输

## 职责

拥有持久通知的版本化编码、Card 2.0 渲染和一次 Webhook 请求。`tibo.post-card.v1` 是队列兼容性契约，不只是临时 HTTP 数据；格式器保留结构化内容，真正的前缀、签名与字节预算在每次发送时应用。旧调试文本仍可解码为测试卡片。

最终签名请求体不超过 19,000 字节，按字符边界截断预览而不拆分卡片；原文存储与迁移语义见 `tibo-architecture`。外部内容使用纯文本并中和提及标记；按钮只打开受限来源链接，不实现回调。

## 边界

传输只执行一次尝试，必须同时验证 HTTP 和业务成功码；输出区分永久错误与可重试错误及冷却提示。持久重试、目标暂停和告警由调用方负责，不能在 HTTP 客户端内部偷偷重发。

不访问业务库，不采集来源、不调用推理，也不保管目标凭据。**未确认的长期约束（由当前分工推断）：**持久通知兼容性和最终渲染留在同一适配边界，存储层只持有其编码内容。
