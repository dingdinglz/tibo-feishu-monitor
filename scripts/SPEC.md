# twscrape 时间线适配器

## 职责

本模块边界是 `fetch.py` 的可执行 JSON 协议，测试脚本不是产品能力。使用 Python 3.10+ 和固定的 twscrape 0.20.1 原始接口读取时间线，以自有严格解析器区分直接时间线条目与递归发现的上下文。

选择原始接口是因为上游生成器可能无声终止，公共解析器还可能把响应写入临时文件。适配器显式观测页面及停滞、关闭敏感日志/遥测/调试转储，未知形状不宣称成功。目标作者的对话内回复可作为独立帖子，嵌套引用只能作为上下文；原生转发不作为目标动态。

## 覆盖与资源边界

固定窗口、续页刷新和从头复核规则由 `tibo-architecture` 定义。补上下文只取一层且有独立次数/时间预算；可选上下文失败不应否定已取得的时间线覆盖证据。取消必须展开异步生成器上下文，不能把正常使用锁遗留到冷却超时。

只使用外部提供的账号库，不拥有业务基线、发送去重、飞书或 AI 推理。账号库仍可能被 twscrape 更新统计及限流状态。上游接口变更需重新验证适配，严格解析不能保证 X 返回全部内容。

**未确认的长期约束：**业务状态继续由 Go 持有，Python 只负责有界读取与协议转换。
